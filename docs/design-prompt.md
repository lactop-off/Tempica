# デザイン生成プロンプト（Claude Design 貼り付け用）

## プロダクト概要
汎用勤怠管理システム（OSS・自己ホスト型）。一般従業員が打刻・各種申請を行い、現場管理者が承認・シフト編成、人事・労務が組織設定・月次締め・給与向けCSV出力を行う業務Webアプリ。多様な勤務形態（固定/フレックス/変形/シフト）に設定で対応し、勤務形態は従業員ごとに割り当てる。PC・スマホ両対応。

## デザインの方向性
- **トーン＆マナー**：清潔・信頼感・効率重視。業務ツールらしい落ち着きと、入力ミスを誘発しない明快さ。情報密度は高めでも整理されて見えること。
- **カラー**：メイン＝信頼感のあるブルー系（例：#2563EB 付近）。状態色＝承認/正常＝グリーン、警告＝アンバー、エラー/超過＝レッド。背景＝ホワイト〜ライトグレー。ダークモード対応が望ましい。
- **タイポグラフィ**：見出し＝太めのサンセリフ。本文＝可読性重視のサンセリフ。時刻・労働時間・残数などの**数字は大きく等幅的に**見やすく。
- **全体レイアウト**：左サイドナビ＋上部ヘッダー（右側に通知ベル・ユーザーメニュー）＋メインエリア。**スマホではボトムナビ＋ハンバーガー**に再構成。全画面レスポンシブ必須。
- **参考イメージ**：国内の業務SaaS（勤怠/人事系）のような明快さ。ただし独自のデザインで。

## 画面ごとの設計

### 画面1：ログイン / 初期セットアップ
- 目的：認証。初回のみ管理者・組織情報の登録ウィザード。
- 主要構成要素：ロゴ、メール／パスワード入力、ログインボタン、（初回）ステップ式フォーム（管理者作成→組織情報→締め日などの基本設定）。
- 状態：通常／入力エラー（認証失敗）／送信中。
- 操作：ログイン→ダッシュボード。初回セットアップ完了→ダッシュボード。

### 画面2：ダッシュボード
- 目的：ロール別に「今やること」を一目で把握。
- 主要構成要素：本日の勤怠サマリカード（出勤状況・労働時間）、承認待ち件数カード（管理者）、アラート（長時間労働・有給取得状況）、クイック打刻ボタン、最近の申請。
- 状態：通常／空（データなし）／読込中（スケルトン）。
- 操作：各カードから該当画面へ遷移。

### 画面3：打刻
- 目的：素早く確実に打刻（スマホ最優先）。
- 主要構成要素：**大きな現在時刻表示**、出勤／退勤／休憩開始／休憩終了の**大型ボタン**、本日の打刻履歴リスト、（モバイル）GPS取得状態の小表示。
- 状態：未打刻（ガイド表示）／打刻済み（次の操作を強調）／読込中（ボタン無効化＋スピナー）／エラー（時刻確定せず再試行）。
- 操作：ボタンタップで打刻し結果トースト表示。

### 画面4：自分の勤怠
- 目的：自分の勤務実績を確認。
- 主要構成要素：月カレンダー（出勤/休暇/残業を色分け）、日次明細テーブル（出退勤・休憩・労働時間・残業）、月次サマリ、月切替。
- 状態：通常／空／読込中。
- 操作：日付選択で明細表示、明細から打刻修正申請へ。

### 画面5：申請作成
- 目的：各種申請をルールに沿って提出。
- 主要構成要素：**種別タブ**（打刻修正/残業/遅刻早退/休暇/直行直帰/出張）、対象日時、理由、種別別フォーム（休暇＝種別・半休/時間、出張＝行先）、**承認経路プレビュー**、送信ボタン。
- 状態：種別未選択（初期）／入力中／送信中／エラー（項目単位メッセージ、締め済み日は選択不可、残数超過は警告）。
- 操作：送信→申請一覧へ。

### 画面6：申請一覧・状況
- 目的：自分の申請の進捗管理。
- 主要構成要素：申請リスト（種別・対象日・ステータスバッジ・現在の承認ステップ）、フィルタ（状態）、詳細パネル、取消ボタン。
- 状態：通常／空（申請なし）／読込中。
- 操作：詳細表示、差戻し分の再申請、取消。

### 画面7：承認一覧（管理者）
- 目的：承認待ちを効率よく処理。
- 主要構成要素：承認待ちリスト（申請者・種別・対象日・内容プレビュー）、承認／差戻しボタン、コメント欄、**一括承認**、代理承認バッジ。
- 状態：空（承認待ちなし）／読込中（スケルトン）／競合エラー（他者処理済みは再取得）。
- 操作：承認/差戻し（差戻しはコメント必須）。

### 画面8：シフト・勤務予定
- 目的：勤務予定の確認・希望提出・編成。
- 主要構成要素：週/月カレンダーグリッド（個人・部署切替）、シフトセル、希望提出フォーム、（管理者）ドラッグ等での編成、予実差異表示。
- 状態：通常／空／読込中。
- 操作：希望提出、（管理者）シフト確定。

### 画面9：勤務形態・就業ルール設定 ＋ 個人割当（人事）
- 目的：組織の勤務形態を定義し、従業員へ割り当てる。
- 主要構成要素：勤務形態テンプレ一覧（固定/フレックス/変形/シフト）、就業ルール編集（所定時間・休憩・**丸め単位/方法**・残業区分）、**従業員割当（開始日・終了日つき）**の一覧と追加フォーム。
- 状態：テンプレ未作成（ガイド）／編集中／エラー（**割当期間の重複**・終了日<開始日はフォーム上で明示）。
- 操作：テンプレ作成・編集、従業員へ割当（期間指定）。

### 画面10：ロール・権限設定（管理者）
- 目的：カスタムRBACの管理。
- 主要構成要素：ロール一覧、**権限マトリクス（機能×操作）**、各権限の**データ範囲セレクタ（自分/部署/拠点/全社）**、テンプレ複製ボタン。
- 状態：空（テンプレから複製を促す）／編集中／保存エラー（変更保持）。
- 操作：ロール複製・編集・保存（管理権限ゼロを防ぐガード）。

### 画面11：月次締め ＋ CSV出力（人事）
- 目的：月次を確定し給与向けCSVを出力。
- 主要構成要素：対象期間選択、**事前チェック結果**（未承認申請・未打刻の件数）、締め実行ボタン、再オープン（権限者）。CSV側＝マッピング選択（項目・並び・エンコーディング utf-8/shift_jis）、プレビュー、ダウンロード。
- 状態：通常／処理中（大型プログレス）／警告（未承認あり・未締めデータ混在）／完了（ダウンロード活性化）。
- 操作：締め実行→CSV出力→ダウンロード。

> 上記以外の周辺画面（休暇管理・組織管理・休暇種別設定・承認経路設定・レポート・通知一覧・監査ログ・個人設定）は「一覧＋詳細/編集」の標準パターンで、同じデザイン言語を適用。

## 主要なユーザーフロー
- **打刻**：ログイン → ダッシュボードのクイック打刻 or 打刻画面 → 出勤/退勤ボタン → 完了トースト。
- **申請→承認**：従業員が申請作成 → 提出 → 管理者に通知 → 承認一覧で承認/差戻し → 結果通知 → 勤怠/休暇残数に反映。
- **月次処理**：人事が月次締め（事前チェック→確定ロック）→ CSVマッピング選択 → 出力 → 給与システムへ取り込み。

## 制約・注意
- **対応デバイス**：PC/タブレット/スマホのレスポンシブ。**打刻はスマホ最優先**で大ボタン・片手操作。
- **アクセシビリティ**：十分なコントラスト、可読フォントサイズ、タップ領域の確保。状態は色だけでなくラベル/アイコンでも区別。
- **言語**：日本語。将来の多言語化に備え、文言は画像に焼き込まない。
- **状態の明示**：空／読込中（スケルトン）／エラーを各画面で必ず用意。エラーは原因と次の操作を提示。
